# Workflow Editor

Visual editor for Roboflow Inference workflows. Drag blocks onto a canvas, wire
them, save to JSON, click **Run**, get results back. Runs **locally**, no
Roboflow API key required.

```
+----------+   palette          inspector
| Toolbar  |   +------+   +-----+----+
+----------+   |      |   |          |
| Palette  |   | ReactFlow canvas    |
|          |   |                     |
+----------+   +----------+----------+
                          | RunPanel |
                          +----------+
```

## Prerequisites

- **Python 3.10 – 3.12** with [`uv`](https://docs.astral.sh/uv/) on `PATH`.
- **Node.js 18+** with either `pnpm` or `npm`.
- A working `examples/local-workflow-demo/` sibling directory — this editor
  imports `real_engine_runner` from there at runtime. If you haven't yet run
  the local-workflow-demo at least once, do that first to download the YOLO
  weights and verify the engine works.
- (Optional, GPU) NVIDIA CUDA 12.x drivers for the default `device="cuda"`
  workflows. Switch to `device="cpu"` in the runtime params if you don't have
  a GPU.

## Quick start

```bash
cd examples/workflow-editor
uv sync                    # creates .venv, installs FastAPI + the inference repo (editable)
cp .env.example .env       # optional — only needed for VLM workflows
./start.sh                 # builds frontend, regenerates manifest if stale, starts backend
```

Then open <http://localhost:7873>.

The first `uv sync` will take a few minutes because it installs the parent
`inference` package editable from `../..`. Subsequent runs are fast.

## What's inside

- **24 pre-introspected blocks** in the palette, grouped by 8 categories
  (model / transformation / analytics / visualization / fusion / formatter /
  flow_control / sink).
- **5 builtin workflows** you can load from the toolbar:
  - `speed` — YOLO → ByteTracker → Velocity → annotate (the local demo's
    Tab 1).
  - `smart` — speed + a Detections-Filter wired to a runtime `keep_classes`
    parameter.
  - `autoannotate` — YOLO-World with prompt-driven classes.
  - `sam3_autoannotate` — SAM3 mask-based autoannotation (requires the
    optional `sam3` extra in your `inference` install).
  - `vlm_only` — calls an OpenRouter-hosted VLM (`openai_compatible@v1`)
    with a JSON-extracting prompt. Needs `OPENROUTER_API_KEY` in `.env`.
- **Save / Load** — `POST /api/workflows/save` writes to
  `saved_workflows/<name>.json`; the file is plain Roboflow Workflow JSON
  and can be fed back into the engine outside the editor.
- **Validate** — `POST /api/workflows/validate` runs `ExecutionEngine.init`
  on the spec without executing it and reports the first error.
- **Run** — `POST /api/workflows/run` accepts a multipart upload, executes
  the workflow once against the image, returns base64 PNGs + serialised
  `sv.Detections` in JSON.

## Environment variables

| Variable               | Used by                                | Required? |
|------------------------|----------------------------------------|-----------|
| `OPENROUTER_API_KEY`   | `openai_compatible@v1` (VLM workflows) | only for VLM |
| `OPENROUTER_BASE_URL`  | same                                   | optional (defaults to `https://openrouter.ai/api/v1`) |
| `OPENROUTER_MODEL`     | same                                   | optional |

If you already configured `examples/local-workflow-demo/.env`, you can
`cp ../local-workflow-demo/.env .env` — the variables are identical.

## Layout

```
workflow-editor/
├── pyproject.toml            # Python deps (this file)
├── start.sh                  # one-shot launcher
├── blocks_manifest.json      # palette catalogue, regenerated by _introspect_blocks.py
├── prebuilt_workflows.json   # id → factory map for the 5 builtins
├── _introspect_blocks.py     # walks inference's block registry → manifest
├── backend/                  # FastAPI app, mounts /api and serves frontend/dist
├── frontend/                 # React + ReactFlow + Vite, builds to frontend/dist/
└── saved_workflows/          # POST /api/workflows/save writes here
```

The backend imports `real_engine_runner` and the three custom plugins
(`local_yolo_plugin`, `yolo_world_plugin`, `sam3_plugin`) from
`../local-workflow-demo/` via `sys.path` — those files are **never** modified
by the editor.

## Development mode (hot reload)

```bash
# Terminal 1 — backend
uv run python -m backend.main

# Terminal 2 — frontend dev server (proxies /api to :7873)
cd frontend
pnpm dev          # or npm run dev
# open http://localhost:5173
```

`start.sh` is for shipping a built artifact; while developing the frontend
use Vite's dev server directly.

## Known limitations (v1)

- **Single-image runs only.** No video / RTSP / streaming. (See
  `examples/local-workflow-demo/` for the streaming demo.)
- **No auth.** Bind only to `localhost` if you don't want strangers running
  workflows on your GPU.
- **Selector kinds are not type-checked in the UI** — you can wire any
  output handle to any input handle. The backend's `/api/workflows/validate`
  endpoint catches mismatches before save.
- **No undo / redo, no minimap, no multi-user collab.** Intentionally.
- **`sam3_autoannotate` 404s** if the `sam3` Python module isn't importable.
  See `examples/local-workflow-demo/BACKENDS.md` for how to install it.

## Troubleshooting

- **`uv sync` fails on `inference`** — check `python_requires` in
  `../../setup.py`; the editor declares `>=3.10,<3.13`.
- **`/api/health` reports no plugins** — make sure
  `../local-workflow-demo/` exists and that `real_engine_runner.py` is
  importable from a plain `python` shell. The editor inherits its
  `WORKFLOWS_PLUGINS` configuration from there.
- **Browser hangs on Run** — the first call per workflow shape compiles a
  fresh `ExecutionEngine` and may take 10–30 s. Subsequent runs hit the
  hash-keyed cache and return in tens of milliseconds.
